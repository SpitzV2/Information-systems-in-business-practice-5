# Принципиальные архитектурные решения (Вариант 2)

## 1. Локализация изменяемого параметра варианта в константах класса
В соответствии с Вариантом 2 верхняя граница часов была снижена с 16 до 15. Значение 15 не размножалось по коду в виде "магических чисел", а вынесено в константу `public static final int MAX_HOURS_PER_DAY = 15;`. Это исключило дублирование логики в проверках и сообщениях об ошибках: при изменении лимита валидация и форматирование сообщений остаются синхронизированными.

## 2. Использование split(";", -1) для обнаружения пустых концевых полей
Стандартный вызов `split(";")` не учитывает пустые элементы в конце строки (например, строка `"8;8;8;8;"` вернула бы массив из 4 элементов). Передача отрицательного лимита `-1` сохраняет концевые разделители, позволяя коду зафиксировать наличие пустого значения на 5-й позиции и выбросить контролируемое исключение с точным номером ошибочного дня, как того требуют обязательные правила работы.
